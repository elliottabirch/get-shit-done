  <name>Task 1: Extend leak-grep.cjs with missing shell patterns</name>
  <files>scripts/leak-grep.cjs</files>
  <action>
Add new shell pattern entries to the SHELL_PATTERNS array in leak-grep.cjs (per D-07/D-09):

1. `mkdir-shell`: `/\bmkdir\b[^\n;]{0,200}\.planning\//` — catches `mkdir -p .planning/...`
2. `cat-shell`: `/\bcat\b[^\n;]{0,200}\.planning\//` — catches `cat .planning/...`
3. `find-shell`: `/\bfind\b[^\n;]{0,200}\.planning\//` — catches `find .planning/...`
4. `ls-shell`: `/\bls\b[^\n;]{0,200}\.planning\//` — catches `ls .planning/...`
5. `git-add-shell`: `/\bgit\s+add\b[^\n;]{0,200}\.planning\//` — catches `git add .planning/...`

IMPORTANT: These patterns must NOT match inside `gsd-sdk query commit --files .planning/...` calls (per Assumption A1). Add a negative lookahead or exclusion comment noting that the existing heuristic (tool/shell keyword + path within 200 chars of a code-fence or tool-call marker) already handles this since `gsd-sdk query` is the keyword, not `git add` literally.

Also add a STAGE_FILTER refinement: `ls-shell` and `find-shell` patterns apply only to workflow/agent/command files (not templates/references where these may appear in documentation prose). Add a zone-aware filter that only reports these patterns when the scanned file is under `get-shit-done/workflows/`, `agents/`, or `commands/gsd/`.

Do NOT create a blanket `.planning/` string match — maintain the pattern-specific detection per Pitfall 1 in RESEARCH.md.
