- `readdirSync(join(projectDir, '.planning', path))` -> `await adapter.listCollection(planningRelativePath(ws, path))`
- `statSync(join(projectDir, '.planning', path))` -> handle via adapter.exists() (for size/mtime checks, read the content and check length; for existence, use exists)

For each file:
1. Add `import { adapterFor } from './helpers.js'` (or accept adapter as parameter if function is already called from a context that has one)
2. Add `import { planningRelativePath } from '../workstream-utils.js'` if not already imported
3. Make the handler functions `async` if they aren't already
4. Replace every `readFileSync`/`existsSync`/`readdirSync`/`statSync` call that targets `.planning/` with the adapter equivalent
5. Remove the `import { readFileSync, existsSync, readdirSync, statSync } from 'node:fs'` import IF no remaining usages exist in the file (some init functions may read non-.planning/ paths like `~/.claude/` which are C2 out-of-scope per REQUIREMENTS.md — those keep raw fs)

**Critical:** init.ts functions that read `~/.claude/...` or `~/.gsd/...` paths are C2 (out of scope) — do NOT migrate those. Only migrate reads against `.planning/` paths.

**Critical:** These functions are called from index.ts registrations. If they become async, ensure the registration closure properly awaits them or that the registry handler contract already supports async (it does — verify by checking existing async handlers).

Remove any now-dead `node:fs` imports after migration. If `readFileSync` is still needed for non-.planning/ reads (C2 paths), keep only that specific import.
