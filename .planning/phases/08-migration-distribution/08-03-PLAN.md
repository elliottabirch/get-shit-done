    # Migration: Markdown to Beads

    This guide covers migrating a project's `.planning/` markdown tree to a
    `bd`-backed store for use with the BeadsAdapter.

    Migration is a **one-time operation** performed at a clean phase
    boundary (phase N complete, phase N+1 not started). Mid-phase
    migration is not supported in v1.0.

    ## Prerequisites

    - `gsd-beads` installed in the project: `npm install gsd-beads`
    - `bd` CLI v1.0.4 or later (Homebrew: `brew install bd`; confirm
      `bd --version`)
    - A clean `.beads/` directory - the migration refuses to run if
      `.beads/` already exists in the project root
    - Current `.planning/` tree is at a committed, clean git state

    ## Command

    From the project root:

    - Preview without writing anything: `gsd-beads migrate --dry-run`
    - Apply: `gsd-beads migrate`

    ## Dry-run output

    `--dry-run` emits a plan-then-apply JSON report listing every noun the
    migration would create. Each entry has:

    - `type`: the noun category (phase, plan, summary, uat, state-event,
      decision, blocker, debug, intel, learnings, ...)
    - `source`: absolute path to the source markdown file
    - `target_bd_id`: the bd id that would be allocated (dry-run shows a
      placeholder; apply mode shows the actual allocated id)
    - `frontmatter_preview`: the first ~10 lines of frontmatter so you can
      spot-check the mapping

    The same JSON shape is emitted in apply mode; you can capture it with
    `gsd-beads migrate > migration-report.json` for a post-migration audit.

    ## Apply behavior

    The migration calls `bd init --from-jsonl` and lets bd auto-generate
    issue ids. **This is non-idempotent**: running `gsd-beads migrate` a
    second time against the same project yields different bd ids. This is
    acceptable in v1.0 because migration is a one-time operation - run
    once at the phase boundary, commit, move on.

    If `.beads/` already exists, the migration refuses to run and exits
    with a diagnostic. Delete `.beads/` (or choose a fresh project) to
    retry.

    ## Backup

    On successful migration, the fork renames your existing markdown tree:

    - `.planning/` becomes `.planning.markdown-backup-<YYYY-MM-DD>/`

    A minimal `.planning/` is then regenerated by the BeadsAdapter on its
    first call (empty scaffolding - the real data lives in `.beads/`).

    ## Rollback

    To return to the markdown backend:

    1. Delete `.beads/`: `rm -rf .beads`
    2. Restore the markdown backup:
       - `rm -rf .planning`
       - `mv .planning.markdown-backup-<DATE> .planning`
    3. Remove or flip `storage.adapter` in `.planning/config.json`
       (set back to `"markdown"` or delete the key).

    ## Post-migration configuration

    After apply, set the adapter in `.planning/config.json`:

    `{ "storage": { "adapter": "beads" } }`

    Future `gsd-sdk query` and workflow commands will route through
    BeadsAdapter. The default (no key, or `"adapter": "markdown"`) remains
    byte-identical to upstream.

    ## Behavior deviations on BeadsAdapter

    A small number of adapter calls behave differently on bd:

    - **`commitPlanningState` is a NOOP** on BeadsAdapter (decision
      `D-2026-05-12-OQ01-BEADS`). Git-based state checkpoints do not exist
      on the bd backend; use `bd` CLI tooling for change auditing.
    - **Binary assets** (UI-review screenshots, sketch PNGs) degrade
      gracefully: write calls log a warning and skip, rather than
      crashing. UI-review workflows continue to function; only the binary
      artifacts are omitted.

    See `adapters/types.ts` `Capabilities` for the machine-readable flags
    each adapter declares.

    ## Verifying the migration

    The paired conformance suite in this repo asserts MarkdownAdapter and
    BeadsAdapter produce equivalent outcomes across every manifest-listed
    method (decision `D-2026-05-12-CONFORM-MANIFEST`). As a post-migration
    safety check you can re-run it from the project root:

    - `npm run test:conformance:paired`

    A clean run confirms the bd store is in a state that round-trips
    equivalently to the markdown tree you migrated from.

    ## Troubleshooting

    - **`Error: .beads/ already exists`** - Delete the directory and
      rerun, or work in a scratch copy of your project.
    - **`Error: bd: command not found`** - Install bd v1.0.4 or later:
      `brew install bd`.
    - **`BeadsAdapterUnavailable: missing-package`** - `gsd-beads` is not
      installed in your project; run `npm install gsd-beads`.
