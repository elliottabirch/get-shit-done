## Capabilities

BeadsAdapter implements the full `StorageAdapter` v1.0 contract, but declares certain capabilities `false` where bd primitives do not support (or do not need to support) the operation. Consumers MUST gate optional operations behind the capability flag (or `has*` type guard).

| Capability | Value | Rationale |
|------------|-------|-----------|
| `record` | `true` | Every `.planning/*.md` file maps to a bd issue. [D-MAPPING] |
| `section` | `true` | L2 sections → sub-records; L3/L4 → anchor-tagged comments. [D-MAPPING] |
| `frontmatter` | `true` | YAML frontmatter round-trips via the format module. |
| `binaryAsset` | `false` | Skip-and-warn — BeadsAdapter does not route binary assets in v1.0. Consumer workflows MUST guard with `hasBinaryAsset(adapter)`. [D-BINARY] Writing throws `UnsupportedCapabilityError('binaryAsset', 'beads')`. |
| `snapshot` | `<true or false — match src/index.ts>` | `<If true>` Via bd store-clone + bead-hash bookmark cutover (D-TXN Outcome B). `<If false>` Plan 01 spike found bd lacks store-clone primitives; this implementation uses the in-memory write-buffer fallback (D-TXN Outcome A); `snapshot()` throws `UnsupportedCapabilityError('snapshot', 'beads')`. |
| `transaction` | `true` | `withTransaction(fn)` is implemented in both outcomes. Required for `pipeline.ts` dry-run. [D-TXN-CAPS] |
| `namedDoc` | `true` | All 8 `NamedDocCategory` values + 'root' discriminated overload. |
| `markdownLockfile` | `false` | bd has no markdown-lockfile primitives. `replaceInCurrentMilestone` + `readModifyWriteRoadmapMd` throw `UnsupportedCapabilityError('markdownLockfile', 'beads')`. Consumers guard with `hasMarkdownLockfile(adapter)`. [OQ-08 resolution] |

| `graphEdges.dependency` | `true` | Synthesizes `{type: 'dependency', confidence: 1.0}` edges from bd `blocks`/`blocked-by`. [D-OQ06] |

## `gsd:*` label namespace

BeadsAdapter uses the following bd labels internally. These are implementation details — do NOT rely on them from consumer code.

| Label prefix | Purpose |
|--------------|---------|
| `gsd:path:<rel-path>` | Maps each `.planning/*.md` file to exactly one bd issue |
| `gsd:section:<L2-heading>` | Tags comments that back L3/L4 nested content (hybrid mapping) |
| `gsd:section:<L2>:<L3>` | Disambiguated anchor path for nested L3 headings under different L2 parents |
| `gsd:section:<L2>:<L3>:<L4>` | L4 disambiguation |
| `gsd:signal:waiting` | Sentinel used by `recordStateSignal({type:'waiting'})` (alternative: WAITING.json issue) |
| `gsd:checkpoints` | Sentinel issue accumulating `commitPlanningState` messages as comments |
| `gsd:scratch:<type>` | Scratch records per Phase 5 D-20 taxonomy |

Label collisions with user-authored bd issues are possible if the user creates issues with `gsd:`-prefixed labels manually. Users should avoid the `gsd:` prefix for their own labels.

## Known limitations

- **Binary assets unsupported.** `writeBinaryAsset` throws. UI-review + sketch workflows need to guard via `hasBinaryAsset(adapter)`. Fix is non-breaking (flip capability + ship blob-store routing) — deferred to post-v1.0 per D-BINARY.
- **Markdown-lockfile helpers unsupported.** `replaceInCurrentMilestone` + `readModifyWriteRoadmapMd` throw. Consumers guard via `hasMarkdownLockfile(adapter)`. Equivalent logic must be expressed via `updateSection` + format module.
- **Semantic edges absent.** `graphs/graph.json` contains only `dependency` edges (from bd blocks/blocked-by). `graphify.cjs`-produced semantic edges are markdown-only. Running `graphify.cjs` against bd is a post-v1.0 follow-up (D-OQ06-DEFERRED).
- **<Outcome A only> Sequential-commit gap.** Mid-transaction failure leaves bd partially committed. Phase 6.1 follow-up tracks closure.
- **Label collisions.** BeadsAdapter uses `gsd:*` labels internally; users must avoid creating bd issues with `gsd:`-prefixed labels manually.
