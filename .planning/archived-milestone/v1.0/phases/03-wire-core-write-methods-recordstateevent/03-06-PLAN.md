<objective>
Land the three-state `StateWriteOutcome` contract designed at the end of the Phase 3 UAT session but not implemented (HANDOFF.json `remaining_tasks[0]`). This gap-closure plan is appended AFTER Plans 03-01..05 shipped; it does not modify those plans or their summaries.

The Phase 3 UAT caught two blocker bugs (`state.add-decision` silent-drop against heading variants; progress-field non-determinism). The defensive fixes landed as three commits:

- `e7c0806a` — broadened decision-heading regex + `appendToOrCreateSection`
- `e325d561` — `syncStateFrontmatter` as the single writer of progress fields
- `08b4054a` — systemic hardening of `blocker_added` / `metric` / `todo_count_update` with create-if-missing + 2 regression tests

Those fixes stopped the silent-drop bleeding but left callers unable to distinguish three semantically-different outcomes they genuinely need to know apart:

1. **Applied** — entry landed (optionally with newly-scaffolded section)
2. **Intentional no-op** — duplicate dedupe fired (re-append of an entry already present)
3. **Structural no-op** — nothing-to-remove (resolving a blocker that isn't there)

Today all three return `Promise<void>` and callers see undifferentiated success. This plan encodes the distinction in the type system, surfaces `created_section` as a typed signal (preserves UAT-fix semantics rather than hiding them), moves duplicate dedupe from caller-side (stateAddRoadmapEvolution) to adapter-side where the rest of the family already lives, and adds regression tests per outcome variant.

Purpose: Give BeadsAdapter (Phase 6, sibling repo) a clean target contract from day one. Without this plan, BeadsAdapter inherits the current two-state contract and we ship a known deficiency into the second adapter.

Output: Updated interface in `adapters/types.ts`; updated MarkdownAdapter dispatchers + internal helpers returning `HelperResult`; 9 SDK caller sites in `state-mutation.ts` consuming outcomes; caller-side dedupe removed from `stateAddRoadmapEvolution`; 2 existing regression tests migrated + 1 new `write-outcome.test.ts` conformance file; ADR `D-2026-05-10-08` in `DECISIONS.md`.

Now refactor `recordStateAppend` (line 679-752). The new dispatcher pattern:
```
async recordStateAppend(event: AppendEvent): Promise<StateWriteOutcome> {
  return this.withTransaction(async () => {
    const raw = (await this.getRecord('STATE.md')) ?? '';
    const body = this.stripFrontmatter(raw);
    let result: HelperResult;

    switch (event.type) {
      case 'decision': {
        const { phase, summary, rationale } = event.payload;
        const entry = `- [Phase ${phase || '?'}]: ${summary}${rationale ? ` — ${rationale}` : ''}`;
        result = this.appendToOrCreateSection(
          body,
          /(###?\s*[^\n]*\b[Dd]ecisions?\b[^\n]*\n)([\s\S]*?)(?=\n###?|\n##[^#]|$)/,
          '## Decisions Made',
          entry,
        );
        break;
      }
      // ... metric, roadmap_evolution, session, forensic_session, quick_task cases
      //     follow the same pattern, each calling its refactored helper ...
    }

    // Translate HelperResult → StateWriteOutcome. Skip disk write when the
    // body didn't change (no-op semantics).
    if (!result.applied) {
      return { applied: false, reason: result.reason ?? 'duplicate' };
    }
    const synced = await this.syncFrontmatter(result.body);
    const normalized = this.normalizeMd(synced);
    await this.putRecord('STATE.md', normalized);
    return result.created_section
      ? { applied: true, created_section: result.created_section }
      : { applied: true };
  });
}
```
