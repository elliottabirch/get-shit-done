**recordStateAppend implementation:**

This method must replicate the `readModifyWriteStateMd` dance: (1) withTransaction, (2) getRecord('STATE.md'), (3) strip frontmatter, (4) find target section by event type, (5) append formatted entry, (6) rebuild frontmatter via `syncStateFrontmatter`, (7) normalize, (8) putRecord.

The section-targeting map (derived from handler analysis):
- `'decision'` -> section regex: `/(###?\s*(?:Decisions|Decisions Made|Accumulated.*Decisions)\s*\n)/i`
- `'metric'` -> section regex: `/(###?\s*(?:Performance\s+Metrics?|Execution\s+Metrics?)\s*\n)/i`
- `'roadmap_evolution'` -> section regex: `/(###?\s*(?:Roadmap\s+Evolution|Phase\s+Changes)\s*\n)/i`
- `'session'` -> section heading: `## Session Continuity`
- `'forensic_session'` -> section heading: `## Forensic Sessions` (or create if missing)
- `'quick_task'` -> section heading: `## Quick Tasks` (or create if missing)

The entry formatting per event type (derived from existing handler logic):
- `'decision'`: `- [Phase ${payload.phase}]: ${payload.summary}${payload.rationale ? ' — ' + payload.rationale : ''}`
- `'metric'`: Table row: `| ${payload.phase} | ${payload.plan} | ${payload.duration} | ${payload.tasks || '-'} | ${payload.files || '-'} |`
- `'roadmap_evolution'`: Formatted using the existing `formatRoadmapEvolutionEntry` logic — `- [${new Date().toISOString().split('T')[0]}] Phase ${payload.phase}: ${payload.action}${payload.note ? ' — ' + payload.note : ''}`
- `'session'`: Update `Last session:` and `Stopped at:` lines in the Session Continuity section
- `'forensic_session'`: `- ${payload.sessionId}: ${payload.findings}`
- `'quick_task'`: `- ${payload.task}${payload.result ? ': ' + payload.result : ''}`

**recordStateMutation implementation:**

Wraps in `withTransaction`. Handles 4 event types:
- `'blocker_added'`: Find `## Blockers` section in STATE.md. Add `- [ ] ${payload.text}` entry. If section not found, create it.
- `'blocker_resolved'`: Find the matching blocker line (`- [ ] ${payload.text}`). Replace `[ ]` with `[x]` or move to resolved subsection.
- `'todo_count_update'`: Update the `## Pending todos` section. Replace existing todo count display or set `(${payload.count} items)`.
- `'deferred_items'`: Find `## Deferred Ideas` section. If action='add', append items. If action='remove', remove matching lines.

Each follows the same pattern: `withTransaction` → `getRecord('STATE.md')` → strip frontmatter → modify body → sync frontmatter → normalize → `putRecord`.
